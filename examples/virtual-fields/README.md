# Virtual association markers / 虚拟关联标记

This public example demonstrates ordinary-rule matching when a content table has **only an ID**, without real document/role columns. It does not implement a workflow engine. Requires current source with virtual-field support; old releases may ignore the flag.

本例展示内容表**只有 ID，没有单据 ID／角色列**时，如何通过普通规则的虚拟标记完成准确关联；不是业务工作流引擎。需要包含虚拟字段支持的当前源码，旧发行版可能忽略此配置。

1. In an authorized empty MySQL test schema, run [mysql-schema.sql](mysql-schema.sql). 先在获授权的空测试库建表示例。
2. `python examples/virtual-fields/create_recipe.py --count 3 --selected 2 > virtual-recipe.json` emits configuration only. 仅生成方案 JSON，不连接数据库。
3. Use MCP `validate_generation`, `preflight_generation` and `save_scheme` with the emitted tables and your private connection profile. Check the preflight response includes `virtualColumns`; an old service that reports these names as missing target columns does not support this example. 再校验、预检、保存普通方案；预检应返回 virtualColumns，旧服务会把标记当成不存在的列。
4. Within write authorization, generate with a retained `request_id`, then poll task/batch receipts. Expected: 3 documents, 6 content records, 2 tasks; each task points to its own document's INPUT/OUTPUT content. 授权后使用稳定请求 ID 生成并核查，预期 3 张主表、6 条内容、2 条任务。
5. Preview and review the exact batch cleanup plan, then explicitly execute it if authorized. Existing/source records remain outside the scope. 清理需先预览审核，再明确执行。

Verification / 核查：

```sql
SELECT COUNT(*) AS mismatches
FROM demo_virtual_tasks
WHERE input_id <> CONCAT(document_id, '-INPUT')
   OR output_id <> CONCAT(document_id, '-OUTPUT');
```

Expected zero. The markers `owner_marker`, `role_marker` and `selected_marker` are not columns in any target table. Their values are generated by ordinary rules, cached for this task, and consumed by same-row references, parent filtering and refMatch. No extension code or ALTER TABLE is required. Missing associations in **pre-existing** rows still need a real source of truth; these markers do not infer unknown business relationships.

预期不匹配数为 0。三个 marker 仅在本轮任务中生成、缓存，用于同表引用、父行筛选和 refMatch，无需扩展代码或改表。**既有数据**中缺失的业务关联仍需要真实依据，不能凭虚拟字段自动猜测。
